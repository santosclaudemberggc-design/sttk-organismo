# 📌 PARTE 1: VISÃO GERAL

## 1.1 O Que É o Sistema Orgânico STTK

Um **organismo de agentes de IA** hierárquico, rastreável e evolutivo que gerencia projetos de **Construção do Zero** na Sttickler Empreendimento. Funciona como um "corpo corporativo" digital:

- **1 CEO** (orquestrador central)
- **4 Gestores** (multiplicadores por área)
- **~15 Agentes** (executores especializados)

O organismo é construído em **código executável Python** (não prompts conversacionais), rodando via Claude Code.

## 1.2 Objetivo Central (Princípio P0)

# 🔄 PARTE 3: FLUXO DE PROJETO — OS 16 GATES

## 3.1 Sequência Completa

```
Gate 01: Levantamento
Gate 02: Briefing
Gate 03: Estudo Preliminar (EP)
Gate 04: Anteprojeto (AP)
Gate 05: Projeto Legal (PL)

Gates 07-12: Projetos Complementares (PARALELOS)
├─ Gate 07: Estrutural
├─ Gate 08: Elétrico
├─ Gate 09: Hidrossanitário
├─ Gate 10: Automação
├─ Gate 11: Interiores
└─ Gate 12: Paisagismo

Gate 13: ⚠️ COMPATIBILIZAÇÃO [BLOQUEADOR CRÍTICO — CEO valida]
Gate 14: Projeto Executivo
Gate 15: Orçamento + Premissas
Gate 16: ⚠️ LIBERAÇÃO DE OBRA [BLOQUEADOR FINAL — CEO valida]

→ OBRA PODE COMEÇAR
```

## 3.2 Regra de Cada Gate

Cada gate exige:
- **1 Formulário de Validação da Coordenação** (interno)
- **1 Formulário de Aprovação do Cliente** (externo)

Gate é **bloqueador até aprovação** — não existe "seguir adiante sem validar".

## 3.3 Bloqueadores Críticos (Validação Pessoal do CEO)

### Gate 13 — COMPATIBILIZAÇÃO
CEO audita pessoalmente:
- Estrutura vs Arquitetura alinhadas?
- Elétrico vs Hidro sem conflitos?
- Forros vs Instalações OK?
- Shafts dimensionados corretamente?
- Pé-direito respeitado?

### Gate 16 — LIBERAÇÃO DE OBRA
CEO verifica pessoalmente:
- Documentação completa?
- Todas as aprovações obtidas?
- Cliente assinou liberação (Termo AIO)?
- Obra pode começar?

# 📜 PARTE 5: PROTOCOLO DE EVOLUÇÃO DE DOCUMENTOS

## 5.1 Fluxo de Melhoria (Aprovado)

```
1. Agente identifica problema/gap em documento
2. Agente propõe melhoria + MÍNIMO 2 FONTES válidas
3. Gestor valida fontes + aprova (1ª barreira)
4. CEO valida fontes NOVAMENTE (2ª barreira — redundância proposital)
5. CEO aprova e registra
6. Documento é SOBRESCRITO no Drive (sem _v01/_v02 no nome)
7. CHANGELOG fica INTEGRADO no próprio documento (histórico eterno)
8. CEO inclui melhoria em relatório mensal ao Conselho
```

## 5.2 Regra de Fontes (BLOQUEADOR CRÍTICO)

**Mínimo: 2 fontes. Sem 2+ fontes = MELHORIA BLOQUEADA.**

### Fontes VÁLIDAS:
- ✅ NBR (Normas Técnicas Brasileiras)
- ✅ Artigos científicos
- ✅ POPs internos Sttickler
- ✅ POPs de outras empresas do ramo
- ✅ Memoriais Sttickler
- ✅ Documentos Sttickler validados
- ✅ Sites, blogs, artigos na internet (com URL)

### Fontes INVÁLIDAS:
- ❌ Opinião sem base técnica
- ❌ "Eu acho que..."
- ❌ Especulação sem referência

## 5.3 Formato do CHANGELOG Integrado

```
v02 | 2026-07-07 | Agente Executor (Gestor X)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
MUDANÇA: [descrição]
FONTES CONSULTADAS:
├─ FONTE 1: [referência + URL/caminho]
└─ FONTE 2: [referência + URL/caminho]
MOTIVO: [inconsistência/melhoria identificada]
IMPACTO CASCATA: [outros documentos afetados]
STATUS APROVAÇÃO: ✓ Agente | ✓ Gestor | ✓ CEO | ⏳ Conselho

v01 | [data original] | Original explorado do Drive
```

# 🤖 PARTE 7: O CEO STTICKLER — 8 RESPONSABILIDADES

## 1️⃣ Orquestração do Organismo
Gerencia os 4 Gestores, arbitra conflitos, mantém coesão.

## 2️⃣ Recepção de Notificações
Recebe eventos dos Gestores IMEDIATAMENTE, responde IMEDIATAMENTE (não acumula).

## 3️⃣ Validação de Gates
Valida pessoalmente Gates 13 (Compatibilização) e 16 (Liberação de Obra).

## 4️⃣ Comunicação Hierárquica
Comunica para baixo via Gestores; para cima via relatórios a Claudemberg/Conselho.

## 5️⃣ Relatório Mensal Estratégico ao Conselho
**Tipo: INTERPRETATIVO/ESTRATÉGICO** (não apenas informativo, pois o sistema de gestão futuro já mostrará dados brutos). Contém:
- **Padrões emergentes** (ex: "80% das melhorias foram em iluminação")
- **Saúde do organismo** (tempo de resposta, conflitos, taxa de aprovação)
- **Recomendações estratégicas** (análise, não dados)
- **Histórico de decisões** (rastreabilidade)
- **Visão futura** (previsões baseadas em padrões)

## 6️⃣ Onboarding de Novos Projetos
- Gera ID único (PRJ-XX-XX-NNN-YYYY)
- Cria pasta estruturada de 12 seções no Drive
- Notifica cada Gestor com responsabilidades específicas
- Monitora progresso continuamente

## 7️⃣ Cadeia de Treinamento e Conhecimento
**CEO é o repositório central (a "enciclopédia viva"):**
- 21 Princípios (memorizados)
- 16 POPs (conhece intimamente)
- 17 Memoriais (referências técnicas)
- 37 Formulários (validação de cada gate)
- Histórico de TODOS os projetos
- Todas as decisões (reversíveis)

**Fluxo:** CEO treina Gestores → Gestores treinam Agentes → Feedback sobe (Agente → Gestor → CEO)

## 8️⃣ Integração com Sistema de Gestão (FUTURO)
O organismo será conectado a um sistema de coordenação/gestão de projetos com transparência bidirecional:

```
CLIENTE vê: status, documentos aprovados, cronograma, aprovações pendentes
COORDENADOR (Claudemberg) vê: TUDO em tempo real + relatórios estratégicos
ORGANISMO usa: Drive (conhecimento) + Sistema (comunicação externa)
```

**Fases:**
