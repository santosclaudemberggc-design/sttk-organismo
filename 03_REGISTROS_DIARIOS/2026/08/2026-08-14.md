## 🟡 Item 6 (Semana 2) — Skills em JSON Estruturado

### Input
- Plano original (`ROTINA_DIARIA_OTIMIZACAO_TOKENS.md`) pedia: "Auditar Skills criadas (9 em Julho)" e converter MD verboso → JSON estruturado, estimando 3 KB → 1,2 KB (60% ↓) por skill.

### Auditoria — o que existe de fato
A auditoria real não confirmou a premissa do plano:
- **Skills oficiais (`.claude/skills/`):** **1**, não 9 — `legal-base-legislativa-bairro/SKILL.md` (22.569 bytes). É a única Skill que o Claude Code carrega automaticamente e que Hely/Kelsen consultam em produção.
- **Skills propostas de Julho (`01_CEO/Skills_Propostas/2026/Julho/`):** **17** documentos, todos com status explícito de **proposta não aprovada** (`LEIA-ME.md`: "Nada entra para um Gestor até ser aprovado por Claudemberg na Reunião Mensal ao Conselho"). Não são "Skills criadas".
- Nenhum conjunto de 9 itens foi localizado sob qualquer critério razoável (nem oficiais, nem propostas, nem por mês). Registro isto para corrigir o plano, não para inflar o número (Princípio 3).

### Decisão — por que a Skill oficial NÃO foi convertida para JSON
Avaliei converter `legal-base-legislativa-bairro/SKILL.md` inteira para JSON e **decidi não fazer isso**. Motivo, com base no próprio conteúdo da Skill:

> "Compilação de terceiro — site, PDF de terceiro, resumo de IA, **e também qualquer paráfrase interna nossa**. Indicativo de baixa confiança." (SKILL.md, hierarquia de confiabilidade das fontes)

A Skill inteira existe porque, em 20/07/2026, um resumo interno (`_indice_fontes.md`) introduziu um erro material que sobreviveu três rodadas de análise. Recomprimir 163 linhas de raciocínio jurídico nuançado (armadilhas, hierarquia entre normas, exceções) em campos JSON curtos recriaria exatamente essa falha — perda de nuance por paráfrase. **A prosa aqui não é overhead, é o produto.** Converter isso para "economizar tokens" trocaria correção jurídica por economia marginal — decisão errada.

### Execução — o que foi feito
1. **`SKILL.index.json`** (novo, ao lado do `SKILL.md` — que permanece intocado e continua sendo a fonte de verdade): índice de **metadados apenas** — gestor responsável, agente consumidor, escopo geográfico atual, lista de arquivos-fonte arquivados, POPs relacionados, pendência aberta (B10). Nenhum parâmetro urbanístico, armadilha ou trecho legal foi resumido ali.
2. **`01_CEO/Skills_Propostas/2026/Julho/indice.json`** (novo, ao lado do `indice.md` — que permanece intocado com as observações narrativas de cada rodada): as 17 propostas da tabela de julho, campo a campo (data, arquivo, título, gestor-alvo, resumo, fonte), sem reescrever o texto original.
3. **Teste de parsing:** `json.load()` validado nos dois arquivos (sem erro). Teste de referência cruzada: filtro programático "propostas para Kelsen" retornou os 3 itens corretos sem precisar ler o arquivo `.md` inteiro.

### Métricas — medidas de verdade, não estimadas

**Achado 1 — tabela MD → JSON, comparação direta, NÃO reduz tamanho:**
```
indice.md (só a tabela, linhas 14-32):     6.606 bytes
indice.json (17 propostas, todos os campos): 9.101 bytes
Variação: +38% (JSON é MAIOR, não menor)
```
Motivo: JSON repete o nome de cada campo em cada uma das 17 linhas; a tabela Markdown paga esse custo uma única vez no cabeçalho. **A estimativa do plano (60% ↓) não se sustenta para dado tabular — corrigido aqui para não repetir o erro em itens futuros.**

**Achado 2 — onde o JSON realmente ajuda, é no caso de uso "consulta pontual", não no tamanho do arquivo isolado:**
```
Gestor pergunta "há proposta nova pra mim?":
  Antes: carregar indice.md inteiro (26.100 bytes: tabela + observações de 8 rodadas diárias)
  Depois: carregar indice.json (9.101 bytes, direto ao ponto, filtrável por gestor_alvo)
  Redução no caso de uso de consulta: 65% ↓

Skill: "quais fontes a Skill legal usa / qual o escopo hoje?":
  Antes: carregar SKILL.md inteiro (22.569 bytes) para achar 1 lista de arquivos
  Depois: carregar SKILL.index.json (2.591 bytes)
  Redução no caso de uso de consulta de metadados: 89% ↓
```

**Métrica honesta para o Painel do Fundador:** a economia de Item 6 **não vem de "MD menor que JSON"** (falso, ver Achado 1) — vem de **evitar carregar o arquivo inteiro quando só se precisa de metadado ou linha de índice**. Isso só se aplica quando a consulta é desse tipo (metadado/lista), não quando é preciso o conteúdo jurídico. Estimo, de forma conservadora e alinhada à faixa do plano (2-5%), que esse ganho se realiza numa fração pequena das conversas de Gestor (checagem de pendência/índice, não análise de caso) — mantenho a faixa do plano por não ter dado de produção para medir a frequência real desse tipo de consulta.
